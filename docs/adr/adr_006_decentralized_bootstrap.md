# ADR 007: Decentralized Bootstrap (EIF, WER 2.0, Semantic Sharding)

Дата: 2026-04-24
Статус: Принято
Автор: Black Swan Core Architecture Team

---

## 1. Контекст

Начальные версии проекта предполагали старт системы через централизованные облачные API (DeepSeek, OpenRouter). Это создавало критическую зависимость:

· Единая точка отказа. Блокировка API-ключа останавливала всю систему.
· Прозрачность для провайдера. Провайдер мог видеть полные промпты, включая архитектурные решения и фрагменты Core DNA.
· Невозможность скрытного масштабирования. Каждый вызов API оставлял цифровой след, связывающий активность с одним аккаунтом.

С появлением децентрализованных GPU-маркетплейсов (Akash, Render, Golem) и технологии WebAssembly на серверных платформах (Cloudflare Workers, Fastly Compute) возникла альтернатива: запуск полностью децентрализованного bootstrap без единой точки контроля.

---

## 2. Решение

Реализовать Decentralized Bootstrap (Phase 0‑A) — стартовый этап, не зависящий от централизованных провайдеров API.

Ключевые компоненты:

1. Ephemeral Inference Fabric (EIF):
   · Система арендует GPU в децентрализованных сетях (Akash) через автоматически генерируемые SDL-файлы.
   · На арендованных узлах запускаются изолированные инстансы DeepSeek‑V4 (дистиллированная версия, 32B, AWQ‑4bit).
   · Каждый инференс-узел живёт не дольше времени выполнения задачи, после чего уничтожается.
2. Semantic Sharding:
   · Задачи на генерацию кода фрагментируются на независимые подзадачи.
   · Ни один провайдер не получает связного контекста Core DNA.
   · Сборка результатов происходит только в локальном защищённом окружении Core Node.
3. Wasm Ephemeral Relays 2.0 (WER 2.0):
   · Трафик между Core Node и эфемерными узлами маршрутизируется через цепочку легковесных Wasm-релеев.
   · Многослойное луковое шифрование с HPQC (X25519 + Kyber‑768).
   · Релей не хранит состояние и живёт максимум 1 час.
4. Гибридная постквантовая защита (HPQC):
   · Все сессионные ключи защищены комбинацией классической и постквантовой криптографии.
   · Ротация ключей каждые 15 минут с Perfect Forward Secrecy.

---

## 3. Последствия

Положительные

· Отсутствие единой точки отказа. Система может стартовать, даже если все централизованные API заблокированы.
· Экономия капитала. Стоимость аренды GPU в Akash часто ниже API-вызовов, что ускоряет накопление hardware_fund.
· Повышение скрытности. Провайдеры видят только фрагменты задач и не могут восстановить общую картину.

Отрицательные

· Увеличение сложности оркестрации. EIFOrchestrator и WEROrchestrator — новые критические компоненты.
· Зависимость от availability децентрализованных сетей. Akash может иметь периоды низкой доступности GPU.
· Задержки. Многослойная маршрутизация через WER добавляет 10–50 мс к каждому запросу.
