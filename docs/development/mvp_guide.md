# Руководство по запуску MVP (Minimum Viable Prototype)

MVP Black Swan — это минимальная, но функциональная версия системы, которая демонстрирует замкнутый экономический цикл: **заработок → оценка риска → реинвестирование**. Прототип не требует физического оборудования и запускается локально на вашем компьютере, используя API глубокой модели для принятия решений и изолированную среду для безопасного выполнения кода.

## Что делает MVP

1. **Анализирует рынок** через тестовые данные (симуляция или реальные стримы).
2. **Принимает решение** с помощью LLM, применяя модифицированный критерий Келли и оценку рисков.
3. **Исполняет микросделку** в изолированной песочнице (gVisor или Docker).
4. **Фиксирует результат** и обновляет историю для последующих итераций.
5. **Демонстрирует экономическую самодостаточность** на дистанции в несколько сотен шагов.

## Предварительные требования

Перед запуском убедитесь, что у вас настроено окружение разработчика согласно [setup.md](setup.md). Дополнительно понадобятся:

- **Docker** (для запуска песочницы; можно использовать и без Docker в упрощённом режиме).
- **API-ключ** к любой совместимой LLM (например, DeepSeek API, OpenRouter или локальный vLLM). Для тестирования можно использовать локальную модель с ограниченной экспертной маской `Vagrant` (20% экспертов), как описано в [architecture/global_state_and_decision_pipeline.md](../architecture/global_state_and_decision_pipeline.md).
- **Python 3.12+** с установленными зависимостями из `mvp/requirements.txt`.

## Структура MVP (в `mvp/`)

```

mvp/
├── README.md           # Краткое описание и быстрый старт
├── requirements.txt    # Python-зависимости (openai, web3, docker-py и т.д.)
├── config.yaml         # Настройки: API-ключ, бюджет, параметры риска

└── cycle_demo.py       # Демонстрация одного полного экономического цикла

```

## Быстрый старт

### 1. Установка зависимостей

```bash
cd mvp
pip install -r requirements.txt
```

## 2. Настройка конфигурации

Отредактируйте config.yaml, указав ваш API-ключ и начальный бюджет (по умолчанию $100 виртуальных):

```yaml
llm:
  provider: "deepseek"          # или openai, local
  api_key: "ваш-ключ"
  model: "deepseek-chat"
  species_mask: "vagrant"       # только для демонстрации
economic:
  initial_capital: 100
  max_risk_per_trade: 0.02      # 2% капитала на сделку
  phi_llm: 0.25                 # коэффициент осторожности Келли
sandbox:
  enabled: true
  runtime: "docker"             # или "gvisor" (требует настройки)
```

## 3. Запуск демонстрационного цикла

```bash
python cycle_demo.py
```

Скрипт выполнит 20 итераций, на каждой из которых:

· Получает текущее состояние рынка (простая симуляция).
· Запрашивает у LLM решение о покупке/продаже.
· Исполняет сделку в песочнице.
· Выводит в консоль изменение капитала и ключевые метрики.

Пример вывода:

```
Iteration 01 | Capital: 100.00 | Decision: buy 0.50 | Profit: +0.23 | Sharpe: 0.12
Iteration 02 | Capital: 100.23 | Decision: hold       | Profit:  0.00 | Sharpe: 0.15
...
```

## 4. (Опционально) Запуск Core Node в фоновом режиме

Для длительной работы запустите Core Node Lite, который будет циклически выполнять цикл OODA и реагировать на события:

```bash
python core_node_lite.py
```

Он будет слушать порт 8000 и предоставлять простой HTTP API для проверки статуса.

## Основные компоненты MVP

### Core Node Lite (core_node_lite.py)

Упрощённая версия Decision Pipeline. Реализует макроцикл OODA:

```python
while True:
    observe()      # сбор телеметрии (рынок, песочница)
    orient()       # обновление World Model (заглушка)
    decide()       # вызов ROIDispatcher
    act()          # выполнение в песочнице
    learn()        # запись результата в память (пока в CSV)
```

### ROIDispatcher (roid_dispatcher.py)

Принимает решение на основе модифицированного критерия Келли и проверяет лимиты риска. Псевдокод:

```python
def evaluate(proposal):
    p = estimate_success_probability(proposal, llm)
    b = estimate_odds(proposal, market_state)
    f_star = p - (1 - p) / b * phi_llm
    f_allowed = min(f_star, max_risk_per_trade)
    if check_convexity(proposal) and sharpe_ratio > threshold:
        return f_allowed
    else:
        return 0.0  # держать
```

Вероятность успеха p оценивается с помощью LLM с маской Vagrant (или Arbtiragius, если доступен). Все параметры калибруются через config.yaml.

### Песочница (sandbox.py)

Безопасно выполняет сгенерированный код или торговые операции. Для MVP используется Docker с ограничениями:

```python
import docker
client = docker.from_env()
container = client.containers.run(
    "python:3.12-slim",
    command=["python", "-c", code],
    detach=True,
    mem_limit="128m",
    network_mode="none",
    read_only=True,
    remove=True
)
```

При использовании gVisor добавляется runtime="runsc". Вся запрещённая активность (eval, exec, сетевые вызовы) блокируется на уровне seccomp-профиля (см. Isolation и Sandbox).

## Ожидаемые результаты

После 200+ итераций MVP должен демонстрировать:

· Положительное математическое ожидание дохода.
· Sharpe ratio > 0.6.
· Отсутствие нарушений лимитов риска.
· Стабильную работу песочницы без утечек.

## Ограничения текущей версии

· Рыночные данные симулируются; нет подключения к реальным биржам.
· LLM может давать сбои при волатильности; для production требуется ансамбль моделей.
· Нет интеграции с CRDT-памятью — история хранится локально.
· Отсутствует BFT-консенсус (рой из одного узла).
