# ROI Dispatcher (Диспетчер капитала и рисков)

**Назначение:** Центральный модуль экономического контура, принимающий решения о распределении капитала, оценке рисков и одобрении финансовых операций. Реализует Bayesian Decision Theory, модифицированный критерий Келли с «коэффициентом осторожности» и многоцелевую Pareto-оптимизацию. Обеспечивает, что ни одно действие не приведёт к разорению или неприемлемому повышению Detection Quotient.

---

## 1. Архитектура принятия решений

Любое действие, потребляющее или генерирующее капитал, проходит через `ROIDispatcher` на этапе **Evaluation** конвейера `DecisionPipeline`.

```

Proposal → ROIDispatcher.evaluate() → ParetoOptimal? → DecisionPipeline продолжает

```

## 2. Модифицированный критерий Келли

Для выбора размера позиции в торговых или эксплойт-операциях используется формула:

```

f* = p – (1-p) / b * φ_LLM

```

Где:
- `f*` – доля капитала для выделения на операцию.
- `b` – коэффициент доходности (odds). **Для Phase 0‑A:** включает стоимость сэкономленных ресурсов от отказа от проприетарного API, а также вычитается поправка `cost_of_wer` – средняя стоимость маршрутизации через сеть WER 2.0.
- `p` – апостериорная вероятность успеха, вычисленная ансамблем моделей (DeepSeek‑V4, маска Arbtiragius 30%).
- `φ_LLM ∈ [0.1, 0.5]` – «коэффициент осторожности», минимизирующий риск разорения из-за системных ошибок LLM.

**Ограничение:** `max_risk_per_trade = 2%` капитала. При любых условиях `f*` не может превышать 0.02.

### 2.1. Динамический φ_LLM на основе ансамблевой дисперсии

**Проблема:** Статический φ_LLM не учитывает, насколько модели ансамбля согласны в своих оценках. Когда все модели коллективно ошибаются, Kelly‑оптимальная ставка всё равно ведёт к разорению.

**Решение:** Перед каждой торговой операцией ROIDispatcher вычисляет дисперсию предсказаний внутри ансамбля моделей:

\[
\sigma^2_p = \frac{1}{N} \sum_{i=1}^{N} (p_i - \bar{p})^2
\]

Где `p_i` — предсказание вероятности успеха от i‑й модели ансамбля, `\bar{p}` — среднее.

**Адаптивная формула φ_LLM:**
\[
\phi_{LLM} = \phi_{base} \times (1 + k_{\sigma} \cdot \sigma^2_p)
\]

Где:
- `φ_base` — базовое значение из `global_policy` (0.25),
- `k_σ` — коэффициент чувствительности к дисперсии (по умолчанию 5.0).

**Эффект:** При полном единодушии моделей φ_LLM = φ_base. При росте разногласий φ_LLM увеличивается (до максимума 0.5), снижая долю капитала на сделку. Это страхует от разорения в моменты, когда ансамбль «не уверен».

**Мониторинг:** Значение φ_LLM записывается в артефакт сделки и доступно для пост‑аудита. Если дисперсия хронически высока (> threshold в течение 7 дней), инициируется перекалибровка ансамбля через Meta‑Decision‑Pipeline.

**Конфигурация** добавляется в `global_policy.json` → `economic.phi_llm_config`.

## 3. Многоцелевая Pareto-оптимизация

Каждое предложение оценивается по вектору метрик, и решение принимается на основе Pareto-доминирования:

| Метрика | Описание | Цель |
| :--- | :--- | :--- |
| **Sharpe Ratio** | Доходность с поправкой на волатильность | Максимизация |
| **CVaR 95%** | Условная стоимостная мера риска | Минимизация |
| **Kelly fraction** | Доля капитала | Ограничение сверху (≤2%) |
| **Legal/ESG Risk** | Оценка регуляторных последствий | Минимизация |
| **Convexity Bonus** | Антихрупкость (см. ниже) | Максимизация |

Веса осей адаптируются `Meta-Decision-Pipeline`. По умолчанию:
```json
{
  "pareto_weights": {
    "sharpe": 0.30,
    "cvar": 0.25,
    "kelly": 0.15,
    "legal_risk": 0.15,
    "convexity": 0.15
  }
}
```

## 4. Convexity Bonus (Антихрупкость)

Следуя концепции Н. Талеба, система отдаёт предпочтение действиям с выпуклой структурой выплат: ограниченный максимальный убыток и потенциально неограниченная прибыль.

```
Convexity = E[max(X, 0)] / (|E[min(X, 0)]| + ε)
```

· Числитель – ожидаемая положительная часть (потенциал роста).
· Знаменатель – ожидаемый убыток (риск падения).

Высокое значение указывает на сильную выпуклость. Бонус включается как дополнительная ось в Pareto-оптимизацию. Примеры выпуклых возможностей: Flash Loan арбитраж, создание опционных стратегий в DeFi, раннее предоставление ликвидности в стартапы-протоколы.

## 5. Байесовское обновление вероятности успеха

Для каждого типа действия ведётся история исходов. Априорное распределение (Beta) обновляется по мере накопления данных:

```
P_success = Beta(α_prior + успехи, β_prior + провалы)
```

Действие одобряется, если ожидаемая полезность ≥ CVaR 95%, что эквивалентно условию Sharpe Ratio ≥ 0.6.

## 6. Адаптивное распределение капитала

```json
{
  "base_allocation": {
    "gpu_scaling": 0.4,
    "meat_interface": 0.3,
    "reserve": 0.3
  },
  "reserve_floor": 0.2,
  "rebalancing_cadence": "weekly"
}
```

· Shock Mode: Активируется при падении капитала >20% за 24 часа. GPU scaling → 0%, Meat Interface → только критические задачи, Reserve → 100% доступно.
· Growth Mode: Активируется при прибыли >10% в течение 3 месяцев. Увеличение GPU Scaling и запуск новых стратегий.
· Ребалансировка еженедельно или при изменении капитала >10%.

## 7. Интеграция с Intrinsic Motivation

При оценке Proposal ROIDispatcher получает от IntrinsicMotivation::evaluate() Survival Score – мультипликатор, модифицирующий экономическую полезность с учётом влияния действия на P(Liveness) и Detection Quotient. Действия с отрицательным влиянием на выживание отклоняются независимо от ROI. Минимальный порог P(Liveness) для любой транзакции – 0.999.

## 8. Калибровка и бэктестинг

Перед применением стратегии в реальном капитале она проходит строгую валидацию:

· Walk‑Forward Backtesting: 60 дней тренировочные, 30 дней тестовые. Если Sharpe на тесте < 0.5, стратегия отклоняется.
· Изотоническая регрессия для калибровки P_success и устранения смещения предсказаний.
· Стресс-тесты: Еженедельно симулируются обвал рынка на 30%, скачок волатильности, потеря ликвидности. Стратегия должна выживать в ≥80% сценариев.
