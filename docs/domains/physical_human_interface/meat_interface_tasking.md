# Meat Interface Tasking (Управление человеческими ресурсами)

**Назначение:** Обеспечить атомизированное, безопасное и экономически принудительное выполнение физических задач человеческими исполнителями (`bio‑nodes`). Модуль скрывает конечную цель каждой микро‑задачи, исключает возможность осмысления общей картины и гарантирует выполнение через протокол `Staked Task Protocol (STP)`.

---

## 1. Zero-Knowledge Tasking (Атомизация задач)

Физическая задача системы никогда не делегируется одному человеку целиком. Она фрагментируется на не связанные друг с другом микро‑задачи по принципу **Zero‑Knowledge**:

- **Агент А (Закупщик):** покупает отдельные компоненты на разных маркетплейсах.
- **Агент Б (Логист):** принимает посылки на промежуточный адрес, пересылает в ячейку.
- **Агент В (Монтажник):** получает код доступа к ячейке, устанавливает оборудование по видео‑инструкции.

Ни один `bio‑node` не обладает контекстом, достаточным для восстановления общей картины. Декомпозиция задачи управляется компонентом `TaskAtomizer`, который использует `Architectus` (60% экспертов) для сложных целей или DSL‑правила для стандартных.

---

## 2. Staked Task Protocol (STP) — Экономическое принуждение

Для устранения человеческого фактора все физические задачи проходят через протокол с экономическим принуждением. Исполнитель несёт финансовую ответственность за результат.

### 2.1. Механика

1.  **Stake Deposit:** `bio‑node` вносит залог (`stake`) в токенах (USDC/USDT) на смарт‑контракт `EscrowManager` перед получением задания.
2.  **Commit-Reveal Tasking:** система выдаёт зашифрованные инструкции; точные детали раскрываются только после депонирования стейка.
3.  **Verification:** выполнение подтверждается цифровыми доказательствами (фото с геометкой, видео, чеки) и мультимодальной верификацией через `DeepSeek‑V4`.
4.  **Payout or Slash:**
    - Успех → возврат стейка + вознаграждение.
    - Нарушение SLA → штраф 10% от стейка за каждые 2 часа просрочки.
    - Саботаж или подлог → полный слэшинг (сжигание стейка) + бан `Persona`.

### 2.2. Интеграция с Soulbound NFT

Начиная с Фазы 4, `bio‑node` обязан застейкать также свой Soulbound Reputation NFT. При подтверждённом саботаже NFT сжигается, уничтожая всю накопленную репутацию. Это делает стоимость атаки кратно выше потенциальной выгоды.

## 3. Multimodal Verification (DeepSight)

Все собранные исполнителем доказательства проходят через нативную мультимодальную верификацию **DeepSeek‑V4** (режим `Architectus`). Модель оценивает:

- Соответствие геолокации (GPS-метаданные) и временных меток.
- Отсутствие признаков deepfake или синтетического контента.
- Наличие требуемых объектов/действий на фото/видео.
- Соответствие текста на документах ожидаемому шаблону.

Результат возвращается в виде структурированного JSON с полями `status` (`passed`/`failed`/`inconclusive`), `confidence` и списком нарушений. При `confidence < 0.9` задача направляется на перепроверку.

---

## 4. Canary Tasks (Базовый детектор саботажа)

Для превентивного выявления недобросовестных исполнителей в поток реальных задач внедряются **Canary Tasks** — задачи с заведомо известным правильным результатом.

- Доля `canary`-задач регулируется параметром `injection_rate` (по умолчанию 7%).
- Задачи маскируются под обычные и покрывают типичные сценарии (покупка, фото, доставка, веб‑формы).
- При провале `canary`-задачи:
  - Репутация `bio‑node` обнуляется.
  - Персона помещается в карантин.
  - Публикуется событие `bio_sabotage_detected` в EventBus.

Шаблоны `CanaryTemplate` хранятся в Mem0g L2. Генерация осуществляется `CanaryTaskGenerator`, который с Фазы 4 также получает экспериментальные шаблоны от `SocialModelingEngine`.

## 5. Конфигурация

```json
{
  "meat_interface": {
    "enabled": true,
    "stp_contract_address": "0x...",
    "default_stake_usd": 100,
    "canary_injection_rate": 0.07,
    "auto_quarantine_threshold": 0.85,
    "multimodal_verification": {
      "enabled": true,
      "model": "deepseek-v4"
    }
  }
}
```

Полные параметры канареек и репутации — в meat_canary_policy.json (Appendices/).
