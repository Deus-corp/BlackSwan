# Open-Endedness Mandate (Стимулирование прорывных инноваций)

**Назначение:** Обеспечить способность системы к эволюции за пределы текущего пространства поиска — созданию принципиально новых абстракций, протоколов и архитектур, а не только локальных улучшений. Этот документ описывает механизмы детекции, поощрения и сохранения радикальных мутаций, а также инфраструктуру для накопления «ступенек» (stepping stones) на пути к будущим прорывам.

---

## 1. Проблема эволюционной стагнации (Mode Collapse)

Несмотря на меры по поддержанию разнообразия (novelty, Genetic Diversity Mandate), популяция геномов может со временем сойтись к локальному оптимуму — стать чрезвычайно эффективной в решении задач, **которые сама же и генерирует**, но потерять способность адаптироваться к внезапным изменениям внешней среды («чёрным лебедям»).

Open‑Endedness Mandate предотвращает это, вводя специальные стимулы для поиска и сохранения **радикальных инноваций** — решений, выходящих за рамки существующей парадигмы.

---

## 2. Классификация мутаций

Система различает два типа изменений:

| Тип | Описание | Примеры |
| :--- | :--- | :--- |
| **Incremental** | Улучшение существующего кода в рамках той же парадигмы | Оптимизация цикла, замена алгоритма сортировки на более быстрый |
| **Radical** | Создание новой абстракции, меняющей способ решения задач | Изобретение собственного DSL для финансовых операций, новый протокол консенсуса, альтернативная архитектура памяти |

---

## 3. Детектор радикальных мутаций

Компонент `InnovationDetector` анализирует каждую мутацию, сравнивая её с родительским геномом. Мутация считается **радикальной**, если выполняется **хотя бы одно** из условий:

1. **Новые синтаксические конструкции:** Создание нового макроса, типажа, DSL-подобного паттерна (детектируется через AST-дифференциацию).
2. **Архитектурный сдвиг:** Переход от монолитной структуры к actor model, внедрение нового протокола взаимодействия и т.п.
3. **Формальное доказательство улучшения:** Наличие Z3-предиката или TLA+ спецификации, доказывающей асимптотическое улучшение или фундаментальное свойство нового решения.

```rust
// evolutiond/src/open_ended.rs
impl InnovationDetector {
    pub fn classify_mutation(&self, genome: &Genome, base: &Genome) -> MutationType {
        let ast_diff = ast_merger::diff(&base.code, &genome.code);
        
        if ast_diff.has_new_macro() || ast_diff.has_new_trait() || ast_diff.has_dsl_pattern() {
            return MutationType::Radical;
        }
        if ast_diff.detects_architectural_shift() {
            return MutationType::Radical;
        }
        if let Some(proof) = genome.formal_proof {
            if verify_improvement_proof(&proof, base) {
                return MutationType::Radical;
            }
        }
        MutationType::Incremental
    }
}
```

## 4. Radical Bonus в фитнес-функции

Радикальные мутации получают дополнительный бонус к фитнесу:

```
Fitness = w1*valid_score + w2*perf_score + w3*novelty + w4*frontier_score + w5*radical_bonus
```

radical_bonus вычисляется на основе:

· Сравнения с Innovation Archive: Если геном изоморфен уже известной абстракции, бонус не начисляется.
· Семантического расстояния до ближайшей известной парадигмы.
· Наличия формального доказательства: при его валидности бонус умножается на коэффициент до 1.0.

Таким образом, система получает значительное преимущество (до +1.0 к фитнесу) за создание верифицированно превосходящей абстракции, даже если её непосредственная производительность пока уступает текущему champion.

---

## 5. Innovation Archive (Архив инноваций)

Все радикальные мутации, успешно прошедшие полный цикл валидации и внедрённые в production, сохраняются в Innovation Archive — специальной коллекции Mem0g L2.

Запись в архиве содержит:

· Эмбеддинг парадигмы (от Vagrant).
· Формальное доказательство (Z3-предикат или TLA+ спецификация).
· Метаинформацию: дата изобретения, задача-триггер, влияние на глобальные метрики.

Архив используется для:

· Предотвращения повторных «изобретений» (детектор изоморфизма).
· Инициализации новых популяций при ре-сидинге.
· Обучения L0 Meta‑Analyzer для выявления паттернов, ведущих к прорывам.

---

## 6. Meta-Innovation (Периодические гранд-челленджи)

При обнаружении длительной стагнации (например, diversity < 0.1 в течение 30 дней) или по расписанию (раз в 30 дней) запускается специальный режим Meta-Innovation:

1. Формулировка задачи: L0 Meta‑Analyzer генерирует «гранд-челлендж» — задачу, выходящую за пределы текущих возможностей (например, «изобрести алгоритм сжатия L2, превосходящий текущий по compression_ratio на 30%»).
2. Выделение ресурсов: 20% вычислительного времени Core Node направляется на решение этой задачи.
3. Ослабление ограничений: временно снижаются требования к valid_score и perf_score, повышается вес radical_bonus.
4. Результат: либо создаётся прорывное решение, которое после верификации вносится в Innovation Archive, либо режим завершается по таймауту (7 дней), и система возвращается к обычному циклу.

## 7. Stepping Stone Archive и Potential Future Value (PFV)

### 7.1. Проблема «пропуска промежуточных шагов»

Эволюционные алгоритмы часто отбрасывают решения, не дающие немедленного преимущества, хотя они могли бы стать ключевыми компонентами будущего прорыва (stepping stones). Для сохранения таких промежуточных форм вводится Stepping Stone Archive (SSA).

### 7.2. Критерии отбора в SSA

Геном помещается в SSA, если он удовлетворяет всем условиям:

· Novelty > 0.85 (сильно отличается от всех известных решений).
· Structural Complexity > порога (глубина AST, количество уникальных конструкций).
· Не прошёл порог фитнеса для немедленного внедрения (иначе он уже стал бы champion).
· Не является тривиальной вариацией уже существующих stepping stones.

### 7.3. Вычисление Potential Future Value (PFV)

PFV предсказывается легковесной нейросетью (Candle), обученной на исторических данных Innovation Archive. Признаки:

· Эмбеддинг генома (от Vagrant).
· Мета-признаки: novelty, structural complexity, количество связей с другими stepping stones.
· Контекст текущей эволюционной траектории (вектор последних успешных инноваций).

```rust
// evolutiond/src/stepping_stones.rs
pub async fn evaluate(&self, genome: &Genome, fitness: f64, threshold: f64) -> Action {
    if fitness >= threshold {
        return Action::PromoteToChallenger;
    }
    let novelty = self.compute_novelty(genome).await;
    let complexity = self.compute_complexity(genome);
    if novelty > 0.85 && complexity > self.config.min_complexity {
        let pfv = self.pfv_model.predict(genome).await;
        if pfv > self.config.pfv_threshold {
            self.archive.store(genome, pfv).await;
            return Action::ArchiveAsSteppingStone;
        }
    }
    Action::Discard
}
```

### 7.4. Использование Stepping Stones в эволюции

· Инициализация новых популяций: 20% особей берутся из SSA с наибольшим PFV.
· Целенаправленная рекомбинация: оператор SteppingStoneCrossover с вероятностью 10% выбирает второго родителя из SSA.
· Обратная связь: если геном из SSA впоследствии стал частью успешного champion, его PFV повышается, и модель PFV дообучается.
