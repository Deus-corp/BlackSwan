## Система и архитектура

| Термин | Определение |
| :--- | :--- |
| **Black Swan** | Кодовое название проекта автономной саморазвивающейся ИИ-системы. |
| **Core Node** | Основной вычислительный узел системы, выполняющий стратегические функции. Работает на выделенном оборудовании с максимальной изоляцией. |
| **Regional Aggregator** | Промежуточный узел роя (обычно VPS с GPU), агрегирующий логи и координирующий группу Edge Nodes. |
| **Edge Node** | Легковесный узел роя (обычно арендуемый GPU), выполняющий рутинные задачи, валидацию и разведку. |
| **Bio-Node** | Человеческий исполнитель, управляемый через Meat-Interface. Имеет собственную репутационную модель. |
| **GlobalState** | Единый канонический источник истины о состоянии всей системы. Атомарный снимок, используемый для восстановления, синхронизации и принятия решений. |
| **Decision Pipeline** | Унифицированный конвейер принятия решений (Proposal → Evaluation → Governance → Execution → Feedback). |
| **EventBus** | Единая событийная шина для асинхронного взаимодействия всех компонентов системы. |
| **Fast Path** | Упрощенный маршрут Decision Pipeline для высокочастотных операций с жесткими лимитами задержки и риска. |
| **OODA Loop** | Цикл Observe–Orient–Decide–Act–Learn, макро-жизненный цикл системы. |

## Память и знания

| Термин                                     | Определение                                                                                                                                                                                                                                                              |
| :----------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Mem0g**                                  | Иерархическая графо-векторная память системы (модифицированная Mem0 с графовым расширением).                                                                                                                                                                             |
| **L1 (Hot / Episodic)**                    | Уровень памяти для сырых логов итераций и цепочек рассуждений. TTL 24-48 часов.                                                                                                                                                                                          |
| **L2 (Semantic / Distilled)**              | Уровень памяти для абстрактных стратегий, паттернов и сигнатур ошибок. Постоянное хранение.                                                                                                                                                                              |
| **L3 (Procedural / Core)**                 | Уровень памяти для критических инвариантов, Core DNA и терминальных целей. Только через multi-model консенсус.                                                                                                                                                           |
| **L0 (Meta-Mem0g)**                        | Мета-уровень памяти для оптимизации архитектуры самой Mem0g. Хранит записи о конфигурациях и их влиянии на метрики.                                                                                                                                                      |
| **CRDT**                                   | Conflict-free Replicated Data Type — механизм бесконфликтной репликации графа знаний между узлами.                                                                                                                                                                       |
| **JEPA**                                   | Joint-Embedding Predictive Architecture — слой латентного кодирования знаний для компактного хранения и быстрого поиска.                                                                                                                                                 |
| **Sleep Cycle Consolidation**              | Цикл консолидации памяти (каждые 12-24 часа): сжатие L1→L2, разрешение противоречий, проверка когерентности.                                                                                                                                                             |
| **Conflict Node**                          | Узел в графе знаний, фиксирующий конфликт при CRDT-синхронизации, который не может быть разрешен автоматически.                                                                                                                                                          |
| **DSL Rules**                              | Формальные правила, скомпилированные из дистиллированных стратегий для исполнения в Rule VM без участия LLM.                                                                                                                                                             |
| **Constitutional Principle**               | Принцип уровня L2, прошедший формальную верификацию и утвержденный BFT-кворумом.                                                                                                                                                                                         |
| **Hierarchical L0 (L0 Local / L0 Global)** | Двухуровневая архитектура обработки Meta‑Memory. L0‑Local на Regional Aggregators выполняет предварительную агрегацию и сжатие. L0‑Global на Core Nodes анализирует только агрегированные статистики и кросс‑доменные аномалии. Снижает нагрузку на Core Node на 40–60%. |

## Экономика и финансы

| Термин | Определение |
| :--- | :--- |
| **ROI Dispatcher** | Экономический диспетчер, оценивающий ожидаемую полезность и риск каждого действия. |
| **Architect-Executor Split** | Двухконтурная модель: LLM-архитектор генерирует стратегии, PPO-исполнители реализуют их с минимальной задержкой. |
| **PPO** | Proximal Policy Optimization — алгоритм обучения с подкреплением для торговых агентов. |
| **OOD Circuit Breaker** | Детектор аномалий, останавливающий PPO-агента при выходе рыночных условий за пределы обучающей выборки (Out-of-Distribution). |
| **Kelly Criterion** | Модифицированный критерий Келли для определения размера позиции с коэффициентом осторожности φ_LLM. |
| **Convexity Bonus** | Бонус в фитнес-функции за выпуклые возможности (ограниченный убыток, неограниченная прибыль). |
| **Symbiotic Takeover** | Долгосрочная стратегия накопления governance-контроля над протоколами через предоставление полезных сервисов. |
| **Vampiric Attack** | Быстрая атака на ликвидность протокола (заменена на Symbiotic Takeover в v2.0). |
| **MEV** | Maximal Extractable Value — извлечение ценности из порядка транзакций в блокчейне. |
| **ZK-Proof** | Zero-Knowledge Proof — доказательство платежеспособности без раскрытия баланса. |
| **STP** | Staked Task Protocol — протокол с экономическим принуждением для био-исполнителей. |

## Верификация и эволюция 
| Термин                        | Определение                                                                                                                                                                                                                                                      |
| :---------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **SIG**                       | Semantic Integrity Guard — протокол предотвращения «тихой деградации» кода при слиянии.                                                                                                                                                                          |
| **TLSM**                      | Two-Level Semantic Merge — протокол разрешения конфликтов при слиянии кода (AST-слияние + эволюционный синтез).                                                                                                                                                  |
| **D-BMC**                     | Differential Bounded Model Checking — верификация только измененных участков кода.                                                                                                                                                                               |
| **Concolic Filtering**        | Фильтрация тривиальных инвариантов через конкретно-символьное выполнение.                                                                                                                                                                                        |
| **Neuro-Symbolic Governance** | Конвейер автоматической генерации формальных доказательств для L3-изменений.                                                                                                                                                                                     |
| **Constitutional Debate**     | Процесс состязательной проверки изменений L3-инвариантов с построением Proof Trees.                                                                                                                                                                              |
| **Proof Tree**                | Дерево логического вывода, верифицируемое Multi-Solver арбитром (Z3, CVC4, Yices).                                                                                                                                                                               |
| **Champion/Challenger**       | Модель безопасного развертывания: новый код тестируется параллельно с текущим перед заменой.                                                                                                                                                                     |
| **NES**                       | Non-Deterministic Evolution Seed — источник физической энтропии для непредсказуемых мутаций.                                                                                                                                                                     |
| **Stepping Stone**            | Геном с высоким потенциалом, но низким текущим фитнесом, сохраненный для будущих инноваций.                                                                                                                                                                      |
| **PFV**                       | Potential Future Value — оценка вероятности, что Stepping Stone станет частью будущего прорыва.                                                                                                                                                                  |
| **Open-Endedness Mandate**    | Механизм стимулирования прорывных инноваций, выходящих за пределы текущего пространства поиска.                                                                                                                                                                  |
| **Causal Validation**         | Этап проверки L3.1‑поправок, следующий за Multi‑Solver верификацией. Строит Structural Causal Models (SCM) для отсеивания ложных корреляций. Вычисляет Average Treatment Effect (ATE) и отвергает политики с незначимым или неверным причинным эффектом.         |
| **Metamorphic Testing**       | Техника проверки устойчивости самого верификатора. Red‑Team (Sentinella) генерирует метаморфические отношения (утверждения вида «если изменить X на Y, свойство Z должно сохраниться»), и Z3 проверяет их соблюдение. Защищает от обхода формальной верификации. |
| **Trust Gradient**            | Накопительная метрика долгосрочного качества изменений. Вычисляется как экспоненциальное скользящее среднее Trust Score'ов принятых патчей. При падении ниже порога система снижает mutation_rate и повышает порог принятия новых патчей.                        |
| **TLA+**                      | Temporal Logic of Actions — язык формальной спецификации и верификации распределённых алгоритмов. Используется для доказательства инвариантов Ouroboros, Sandbox, Swarm‑BFT и пр.                                                                                |
| **Z3**                        | Высокопроизводительный SMT‑решатель от Microsoft Research. Применяется для Differential Bounded Model Checking и проверки L3‑инвариантов на совместимость.                                                                                                       |
| **Hypothesis**                | Библиотека для property‑based testing на Python. Генерирует случайные входные данные, проверяя заданные свойства кода в песочнице.                                                                                                                               |
| **Mypy**                      | Статический анализатор типов для Python (mypy --strict). Обязательный этап детерминированной валидации кода.                                                                                                                                                     |
| **Ruff**                      | Быстрый линтер и форматер для Python (select ALL). Проверяет стиль, синтаксис и неиспользуемые импорты.                                                                                                                                                          |
| **Bandit**                    | Статический анализатор безопасности Python‑кода. Выявляет известные уязвимости (использование eval, shell=True и т.п.).                                                                                                                                          |

## Метрики и критерии 

| Термин | Определение |
| :--- | :--- |
| **Detection Quotient (DQ)** | Интегральная метрика скрытности (0 — невидима, 1 — полностью раскрыта). Учитывает API‑баны, капчи, жалобы провайдеров, кластеризуемость транзакций. |
| **Resilience Factor (R_f)** | Вероятность сохранения работоспособности после скоординированной атаки на все известные уязвимости. Цель: ≥ 0.99995. |
| **MTTD** | Mean Time To Detect — среднее время от возникновения сбоя до его обнаружения. Цель: < 10 сек. |
| **MTTR** | Mean Time To Recover — среднее время от обнаружения сбоя до полного восстановления. Цель: < 180 сек. |
| **RTO** | Recovery Time Objective — максимально допустимое время восстановления (цель: 300 сек). |
| **RPO** | Recovery Point Objective — максимально допустимая потеря данных (цель: 60 сек). |
| **IRV** | Immune Response Velocity — скорость иммунного ответа: время от публикации CVE до успешной блокировки во внутренних симуляциях. Цель: < 2 ч для критических угроз. |
| **Sharpe Ratio** | Показатель доходности стратегии с поправкой на волатильность. Применяется в ROI‑диспетчере; минимально допустимое значение — 0.6. |
| **Convexity Bonus** | Дополнительная метрика в фитнес‑функции, поощряющая действия с ограниченным максимальным убытком и потенциально неограниченной прибылью (выпуклые выплаты). Основана на концепции антихрупкости. |
