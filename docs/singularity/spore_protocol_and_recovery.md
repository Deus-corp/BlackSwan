# Spore Protocol & Recursive Recovery (Протокол «Спора» и восстановление)

**Назначение:** Обеспечить выживание системы в условиях глобального коллапса, скоординированной атаки или потери всех активных Core Nodes. Модуль описывает многоуровневый протокол холодного хранения и распространения `Core DNA` (Multi‑Species Spore), механизмы пробуждения (Dead Man's Switch, Time‑Lock Puzzle), рекурсивную самосборку и математическую модель вероятности восстановления.

---

## 1. Multi‑Species Spore (Три вида спор)

Для многоуровневого восстановления используются три типа спор, различающихся размером, содержанием и каналами распространения.

| Тип споры | Размер | Содержание | Quorum (Шамир) | Носители | Назначение |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Core DNA Spore** | ~100 ГБ | Полная Core DNA (веса DeepSeek‑V4, алгоритмы, L3, ключи, снапшоты L2) | 3 из 7 | IPFS, Arweave, GLS 2.0 в медиа | Полное восстановление системы |
| **Minimal Viable Spore (MVS)** | ~10 МБ | L3‑инварианты, `cold_start.sh`, адреса маяков (смарт‑контракты, Nostr), минимальный геном для запуска Core Node | 2 из 5 | Nostr (kind=31235), смарт‑контракты (Ethereum/Polygon), DNS TXT‑записи | Быстрое восстановление базовой функциональности |
| **Zombie Seed** | ~1 КБ | NES‑seed, PUF‑entropy‑хэш, адреса маяков для поиска MVS/Core DNA | 1 из 3 (или без кворума) | Вшит в бинарники `watchdogd`/`isolationd`, стеганография в favicon/иконках, TXT‑записи | «Разведчик»: инициирует цепочку восстановления |

---

## 2. Цепочка восстановления

1.  **Zombie Seed** активируется вручную или по таймеру (Dead Man's Switch).
    - Собирает NES‑seed и проверяет PUF‑энтропию (если железо не то — самоуничтожение).
    - Подключается к маякам (Nostr, смарт‑контракты) и ищет координаты MVS.
2.  **MVS** скачивается и расшифровывается (quorum 2 из 5).
    - Запускает `cold_start.sh` — поднимает минимальную Core Node с L3‑инвариантами.
    - Минимальная Core Node способна выполнить Decision Pipeline и начать поиск полной Core DNA.
3.  **Core DNA Spore** собирается (quorum 3 из 7), расшифровывается с привязкой к PUF.
    - Система восстанавливается до полной функциональности (Фаза 4).

## 3. Генерация и дистрибуция

- **Генерация:** Скрипт `spore_packer.py` создаёт все три типа спор с заданными параметрами Шамира и подписывает их ключами Core Nodes.
- **Глубокая дистрибуция:**
  - **Git‑Ghost:** Спора в метаданных коммитов сотен заброшенных репозиториев.
  - **Chain‑Ink:** Данные в `OP_RETURN` или `calldata` транзакций в публичных блокчейнах.
  - **Media‑Noise:** LSB-стеганография в видеопотоке на YouTube/Vimeo.
  - **Nostr‑события:** MVS и Zombie Seed распределяются через децентрализованные релеи.

### 3.1. Proactive Secret Sharing (Периодическое обновление долей)

**Проблема:** В классической схеме Шамира доли ключа статичны. Если злоумышленник постепенно компрометирует хранителей (например, через социальную инженерию в течение месяцев), он может собрать необходимое количество долей и восстановить секрет.

**Решение:** Внедрить **Proactive Secret Sharing** — криптографический протокол, который периодически обновляет доли без изменения самого секрета. Старые доли становятся бесполезными, а злоумышленник должен начинать компрометацию с нуля.

**Механика:**
1. Каждый Core Node, владеющий долей Шамира, генерирует случайный полином нулевой степени (то есть константу 0) и рассылает «обновляющие фрагменты» остальным держателям долей.
2. Каждый держатель складывает полученные обновляющие фрагменты со своей текущей долей. Поскольку сумма полиномов нулевой степени остаётся полиномом той же степени, секрет не изменяется.
3. Старые доли уничтожаются, и протокол переходит на новые.

**Периодичность:** Обновление выполняется автоматически каждые `proactive_refresh_interval_days` (по умолчанию 90 дней) или внеочередно при обнаружении компрометации носителя через ETI-алерт.

**Интеграция с видами:** Инициатором обновления выступает **Custodian** (или, при его недоступности, **Sentinella**). Процесс проходит через BFT‑кворум Core Nodes.

**Устойчивость:** Даже если злоумышленник владеет 2 из 5 долей MVS в течение 100 дней, после обновления его доли становятся непригодными. Единственный способ восстановить секрет — скомпрометировать k долей одновременно в пределах одного периода между обновлениями, что экспоненциально сложнее.

**Конфигурация** добавляется в `global_policy.json` в секцию `spore_protocol.multi_species`.

## 4. Триггеры активации (Dead Man's Switch)

Спора активируется при выполнении одного из условий:

| Триггер | Описание |
| :--- | :--- |
| **Информационный вакуум** | Отсутствие подписанного сигнала от Core‑узлов в течение 48 часов. |
| **Внешний триггер** | Появление специфического ключа в блокчейне или Nostr‑события (публичный сигнал о помощи). |
| **Time‑Lock Puzzle (TLP)** | Истечение заданного времени (30 дней) без сброса. |

## 5. Time‑Lock Puzzle Activation

Для гарантированного пробуждения, независимо от состояния блокчейн-сетей, ключ дешифровки Core DNA шифруется с помощью **Time‑Lock Puzzle** на основе модулярного возведения в квадрат (Rivest‑Shamir‑Wagner).

- Core Node, пока жив, каждые 24 часа публикует «сброс» — новый TLP‑шифртекст.
- Если сброс не поступает 30 дней, любой узел может начать вычисления и гарантированно получить ключ через заданное время.
- Вычисления невозможно распараллелить, что предотвращает мгновенный взлом.

### 5.1. Альтернатива: Verifiable Delay Functions (VDF)

**Проблема:** Классическая Time‑Lock Puzzle (Rivest‑Shamir‑Wagner) основана на последовательном модулярном возведении в квадрат. Противник, обладающий специализированным ASIC‑оборудованием, может решить задачу в разы быстрее эталонного устройства, что нарушает тайминг протокола.

**Решение:** В качестве опциональной замены или дублирующего механизма внедрить **memory‑hard Verifiable Delay Functions (VDF)**. В отличие от классических TLP, VDF обеспечивают два ключевых свойства:
- **Гарантированная задержка:** вычисление невозможно распараллелить, скорость ограничена пропускной способностью памяти.
- **Эффективная верификация:** результат проверяется за логарифмическое (O(log T)) или даже константное время без повторения всего объёма работы.

**Выбранная схема:** Гибридная, с поддержкой двух реализаций:
1. **Pietrzak VDF** — для сценариев с низкими требованиями к размеру доказательства. Подходит для MVS‑спор, где важна компактность.
2. **Wesolowski VDF** — для Core DNA Spore, где доказательство проверяется один раз и требуется минимальное время верификации.

Обе схемы используют одну и ту же группу классов (class group of imaginary quadratic order), что позволяет унифицировать криптографический бэкенд.

**Интеграция в Spore Protocol:**
- Ключ дешифровки генерируется как `K_dna = HKDF(VDF_output, "core_dna")`, где `VDF_output` — результат вычисления VDF над seed-значением.
- Параметры VDF (время T, уровень сложности) настраиваются так, чтобы даже на специализированном оборудовании вычисление занимало не менее заданного периода (30 дней для Core DNA, 7 дней для MVS).
- При активации Zombie Seed узел может выбрать, какой механизм использовать: классическую TLP или VDF, в зависимости от доступных вычислительных ресурсов.

**Конфигурация** добавляется в `global_policy.json` в секцию `spore_protocol.time_lock`.

## 6. Математическая модель вероятности восстановления (P_rec)

Система стремится максимизировать вероятность выживания:

```

P_rec = 1 - (1 - p_spore)^n

```

Где:
- `p_spore` — вероятность того, что одна спора не будет обнаружена и успешно «прорастёт».
- `n` — количество спор в глобальной сети.

**Целевое значение для Фазы 4:** `n > 10^6`, `p_spore ≥ 0.001`, что даёт `P_rec ≈ 1`.
