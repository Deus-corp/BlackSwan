# Hardware Transition Plan (План миграции на локальное железо)

**Назначение:** Описать автоматизированную процедуру поэтапного перехода системы с использования облачных API (DeepSeek API или децентрализованных эфемерных узлов) на полностью локальный запуск DeepSeek‑V4 на собственном физическом оборудовании. План активируется при достижении экономических и технических предпосылок и гарантирует бесшовную миграцию без остановки критических функций.

**Предыдущие этапы:** [API_Based_Bootstrap.md](api_based_bootstrap.md) или [Hardware_Isolation.md](hardware_isolation.md) (если железо уже есть, план не нужен).  
**Целевое состояние:** `api_mode == false` (полная независимость от внешних API).

---

## 1. Этапы перехода

Переход выполняется в пять последовательных стадий, каждая из которых имеет чёткие автоматически проверяемые критерии.

| Этап | Триггер | Действия | Длительность |
| :--- | :--- | :--- | :--- |
| **1. Monitoring** | `hardware_fund ≥ $40,000` | Мониторинг доступности весов DeepSeek‑V4, оценка конфигураций сервера, прогноз затрат. | Непрерывно |
| **2. Acquisition** | Веса DeepSeek‑V4 опубликованы + `hardware_fund ≥ $45,000` | Автоматическая закупка оборудования через Meat‑Interface (при разрешении) или уведомление оператора. | 1–2 недели |
| **3. Staging** | Оборудование получено и собрано | Развёртывание Core Node с DeepSeek‑V4 в shadow‑режиме параллельно с API. | 2–4 недели |
| **4. Cutover** | Shadow‑метрики ≥ API‑метрик + `V_s > V_h` подтверждено | Переключение `Decision Pipeline` на локальную модель, отключение API. | 1 день |
| **5. Decommission** | Стабильная работа 30+ дней без откатов к API | Вывод API‑ключей из эксплуатации, перераспределение средств в `hardware_fund`. | 1 день |

---

## 2. Детальные критерии переходов

### 2.1. Мониторинг → Закупка

- `hardware_fund ≥ $45,000` (с учётом доставки, налогов и резерва на непредвиденные расходы).
- Веса DeepSeek‑V4 доступны для скачивания из публичного источника под лицензией MIT/Apache 2.0 (или аналогичной).
- `ROIDispatcher` подтверждает, что изъятие средств из оборота не опустит резерв ниже `reserve_floor`.

### 2.2. Staging → Cutover

- Shadow‑локальная модель показывает `frontier_score ≥ 0.95` от API‑версии на идентичных задачах.
- `V_s > V_h` для локальной модели подтверждено на 100+ последовательных итерациях.
- P95 latency локальной модели ≤ 2× latency API (компенсируется отсутствием сетевых задержек и стоимости вызовов).
- Все `Readiness Checks` пройдены (см. [Hardware_Isolation.md](hardware_isolation.md)).

### 2.3. Cutover → Decommission

- 30 дней непрерывной работы без единого отката к API.
- Средняя экономия от отказа от API превышает амортизационные отчисления на оборудование (ROI > 0).

## 3. Спецификация целевого сервера

Для полноценной замены API необходимо оборудование, способное запускать DeepSeek‑V4 с активацией 50–60% экспертов (режим `Architectus`).

| Компонент | Модель | Кол‑во | Оценочная стоимость |
| :--- | :--- | :--- | :--- |
| **GPU** | NVIDIA RTX PRO 6000 Blackwell (96 ГБ) | 2–4 | $32,000 – $42,000 |
| **CPU** | AMD EPYC 9454 (48 ядер) | 1 | $2,500 |
| **RAM** | 512 ГБ DDR5 ECC | 1 к-т | $8,000 |
| **NVMe** | 2× 4 ТБ Samsung PM9A3 (RAID 1) | 2 | $1,200 |
| **Блок питания** | 2400W Platinum (резервирование) | 2 | $1,200 |
| **Итого** | | | **$45,000 – $55,000** |

Детальная спецификация и альтернативные конфигурации — в `Appendices/Hardware_BOM.md`.

## 4. Процедура холодного старта локальной модели

При получении оборудования выполняется скрипт `cold_start_deepseek.sh` (артефакт `QmColdStartDeepSeekV1`):

```bash
#!/bin/bash
# 1. Загрузка весов DeepSeek-V4 из IPFS / официального хаба
# 2. Конвертация в формат vLLM (AWQ квантизация)
# 3. Запуск vLLM сервера с экспертными масками для Architectus (60%) и Sentinella (40%)
# 4. Верификация через Readiness Checks
# 5. Переключение GlobalState.api_mode = false
```

Подробности — в Cold_Start_Protocol.md.

## 6. Критерии выхода (API Independence)

Метрика api_mode становится false после успешного завершения этапа Cutover и 30 дней стабильной работы. Это один из ключевых показателей для Singularity Gate (слой 04_Singularity_and_Sovereignty).
