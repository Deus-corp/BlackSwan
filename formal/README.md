# Формальные спецификации (TLA+)

В этом каталоге хранятся математические модели критических компонентов системы Black Swan, написанные на языке **TLA+** (Temporal Logic of Actions). Формальная верификация — один из главных архитектурных принципов проекта: жизненно важные инварианты доказываются до внедрения в production.

## Структура

- `tla/` — модели TLA+ (`.tla`) и конфигурации для TLC (`.cfg`)
- `alloy/` — (зарезервировано для моделей Alloy)

## Как работать с TLA+ Toolbox

### Установка

1. Убедитесь, что установлена **Java 11** или новее (нужна для запуска TLC).
2. Скачайте [TLA+ Toolbox](https://lamport.azurewebsites.net/tla/toolbox.html) для вашей операционной системы.
3. Распакуйте архив и запустите `toolbox` (Windows: `toolbox.exe`, Linux/macOS: `./toolbox`).

### Открытие и запуск модели

#### Через графический интерфейс

1. Запустите Toolbox и создайте новую спецификацию: **File → New → TLA+ Specification**.
2. Скопируйте содержимое нужного файла из `tla/` (например, [`NodeLifecycle.tla`](tla/NodeLifecycle.tla)) в редактор или откройте файл напрямую: **File → Open File…**.
3. Создайте новую модель: выберите в дереве проекта спецификацию, нажмите **New Model…** и следуйте мастеру.  
   Или воспользуйтесь готовой конфигурацией (`.cfg`), если она есть в `tla/`. Для `NodeLifecycle.tla` конфигурация пока задаётся вручную (см. ниже).
4. В интерфейсе модели во вкладке **Model Overview** задайте значения констант:
   - `MaxBootAttempts` ← 3
   - `MaxUptime` ← 10
5. На вкладке **Invariants** добавьте проверяемые инварианты (если их нет по умолчанию):
   - `NoResurrection`
   - `BootLimitRespected`
   - `AliveImpliesBooted`
6. Запустите проверку: **Run → TLC Model Checker** (или кнопка на панели инструментов). TLC проверит инварианты на всех достижимых состояниях.

#### Из командной строки

Для автоматизации или удалённого запуска используйте `tla2tools.jar`:

```bash
# Загрузите TLA2Tools (если нет Toolbox)
wget https://github.com/tlaplus/tlaplus/releases/download/v1.8/tla2tools.jar

# Создайте конфигурационный файл NodeLifecycle.cfg:
cat > NodeLifecycle.cfg << EOF
SPECIFICATION Spec
CONSTANTS
  MaxBootAttempts = 3
  MaxUptime = 10
INVARIANT
  NoResurrection
  BootLimitRespected
  AliveImpliesBooted
EOF

# Запустите проверку
java -cp tla2tools.jar tlc2.TLC NodeLifecycle -config NodeLifecycle.cfg
```

Ожидаемый результат: Model checking completed. No error has been found.
Если инвариант нарушен, TLC выведет контрпример — последовательность действий, приводящую к ошибке.

Что проверяет NodeLifecycle.tla

Модель описывает конечный автомат одного узла с состояниями Bootstrap, Alive, Dead и переходами:

· успешная загрузка,
· штатная работа (инкремент времени жизни),
· смерть по исчерпанию времени жизни или превышению попыток загрузки,
· протоколы экстренной смерти (LastBreath, Sting).

Доказанные инварианты:

· NoResurrection: мёртвый узел никогда не возвращается в живое состояние.
· BootLimitRespected: счётчик загрузок не превышает MaxBootAttempts.
· AliveImpliesBooted: живой узел обязательно совершил хотя бы одну успешную загрузку.

Эти свойства гарантируют, что узел всегда завершает работу в безопасном состоянии.

Добавление новых моделей

1. Создайте .tla файл в подкаталоге tla/.
2. Опишите переменные, начальное состояние, переходы и инварианты.
3. Добавьте конфигурацию .cfg (или документируйте константы, чтобы пользователь мог создать модель в Toolbox).
4. Проверьте модель через TLC, убедитесь в отсутствии ошибок.
5. Включите запуск модели в CI/CD (настраивается в .github/workflows/formal-verification.yml).

Интеграция с CI/CD

Проверка TLA+ спецификаций будет добавлена в GitHub Actions при переходе к разработке прототипа (TRL-3+). Для этого используется tla2tools.jar, а результаты сравниваются с эталонными логами.
